# CLAUDE.md — контекст проекта (читай целиком в начале каждого запуска)

## Ситуация
Хакатон корпоративного акселератора МТС Беларусь (Spacecorpacc, Минск). Трек: «ИИ-агент для
фиксации договорённостей в телефонных разговорах». Команда — двое: Patek (продукт, питч, тоже
пишет код) и один разработчик. На разработку до отбора ~полтора дня. Питч — 3 минуты.
Ты работаешь НОЧЬЮ автономно, пока команда спит. Утром они прочитают MORNING.md и продолжат.
Цель ночи: максимум готового, проверенного и запускаемого кода и материалов, чтобы утром
команда только записала реальные звонки и довела демо.

## Продукт и главная мысль питча
«Не саммари звонка, а РЕЕСТР ОБЕЩАНИЙ, который сам проверяет выполнение.»
После звонка система извлекает обязательства обеих сторон (кто, кому, что, к какому сроку,
сумма, условие, статус), у каждого — дословная цитата и таймкод в записи (кнопка ▶ играет
с этого места), человек подтверждает/правит/отклоняет. Карточка клиента в две колонки:
«Мы должны» / «Нам должны». Во ВТОРОМ звонке тому же клиенту система находит упоминание
выполнения («КП получили») и ПРЕДЛАГАЕТ закрыть обязательство (никогда не закрывает сама).
Это и есть вау-момент демо: этого нет ни у одного найденного конкурента.

Конкуренты (кратко): Битрикс24 BitrixGPT (резюме звонка + заполнение полей сделки),
Yandex SpeechSense и МТС Exolve (саммари → CRM), Gong (next steps, напоминания), Zoom Phone
(задачи из action items), Dialpad (action items), AWS Transcribe Call Analytics (action items
со смещениями в тексте, только EN), SIPSIM.by (BY: саммари в amoCRM), Bewise (amoCRM: задача,
если не назначен следующий шаг). Наше отличие: обязательство как сущность со статусами и
двумя сторонами; нормализация дат; закрытие по следующему звонку; цитата + таймкод;
развёртывание внутри контура заказчика (on-prem).

## Вход и сценарий
- Звук: телефонный, 8 кГц, G.711 (A-law). Предпочтительно ДВУХКАНАЛЬНЫЙ (левый канал —
  сотрудник, правый — клиент): тогда диаризация не нужна, автор каждой фразы известен.
- Источник в продукте — «Виртуальная АТС» МТС (в демо заменяется загрузкой wav-файла).
- Режим: разбор ПОСЛЕ звонка (не реальное время).
- Язык: русский. Белорусский — только дорожная карта, не делать.
- Часовой пояс: Europe/Minsk (UTC+3). Дата звонка — опорная для всех относительных дат.

## Конвейер
wav (стерео) → разделить каналы → ASR по каждому каналу (фразы с временем) → слить по времени →
расшифровка (контракт ниже) → LLM извлекает обязательства по JSON-схеме → КОД: проверка цитат,
время и автор из расшифровки, нормализация дат, флаги → хранилище → интерфейс.
Второй звонок: открытые обязательства клиента + новая расшифровка → LLM предлагает закрытия →
проверка цитат → интерфейс («Предложено закрыть»).

Принцип: модель ПРЕДЛАГАЕТ, детерминированный КОД ПРОВЕРЯЕТ. LLM не считает даты и не
ставит время/автора — это делает код по расшифровке.

## ASR
- Основной: T-one (github.com/voicekit-team/T-one, Apache 2.0, обучен на русской телефонии,
  CTC, ~71M параметров, встроенный разделитель фраз с временем: StreamingCTCPipeline,
  forward_offline). Запускать на КАЖДОМ канале отдельно. Зависимость KenLM собирается из
  исходников — может капризничать.
- Запасной: GigaAM-v3 (github.com/salute-developers/GigaAM, MIT; варианты e2e_ctc / e2e_rnnt;
  .transcribe принимает до 25 с → резать Silero VAD (MIT) на отрезки).
- Диаризацию (pyannote) НЕ делаем: при стерео не нужна. ВАЖНО: pyannote community-1 сам
  сводит стерео в моно — никогда не подавать ему стерео. На телефонном корпусе CALLHOME у него
  26,7% DER — это аргумент за стерео.

## LLM
- Решение команды: продукт НЕ строится на моделях/API Anthropic.
- Доступ к LLM — через OpenAI-совместимый интерфейс (python-пакет openai, base_url/model/api_key
  из .env или config). Тогда локальная модель (Ollama, vLLM, llama.cpp server) и облачные
  API меняются строкой конфига. Предпочтение в продукте — локальная Qwen3 (Apache 2.0).
- Облачных ключей НЕТ. Обязателен mock-бэкенд (детерминированный), чтобы весь конвейер,
  тесты и интерфейс работали без LLM.
- Структурированный вывод: response_format json_schema, если поддерживается; иначе JSON-режим
  + валидация pydantic + один повтор с сообщением об ошибке.
- Промпты — на русском, с 2–3 короткими примерами. Правила в промпте: только явные
  обязательства; статус по формулировке («наверное», «может», «не точно» → tentative);
  «если …» → conditional + condition; замена срока («нет, лучше к среде») → новое обязательство
  с replaces; цитаты ДОСЛОВНЫЕ; срок отдавать разложенным (raw/type/value), не вычислять дату.

## Контракт 1: расшифровка звонка (data/transcripts/<call_id>.json)
{
  "call_id": "call_001",
  "call_datetime": "2026-10-13T14:05:00+03:00",
  "client_phone": "+375291234567",
  "client_name": "Иван Петрович",          // может быть null
  "direction": "outbound",                  // outbound | inbound
  "audio_path": "data/audio/call_001.wav",  // может быть null для синтетики
  "segments": [
    {"speaker": "employee", "start": 12.4, "end": 17.9,
     "text": "коммерческое предложение я вам пришлю до пятницы"},
    {"speaker": "client", "start": 20.1, "end": 26.3,
     "text": "хорошо по оплате первую часть тысяч пять переведём до двадцатого"}
  ]
}

## Контракт 2: обязательство
{
  "id": "c_0001", "client_phone": "+375291234567", "call_id": "call_001",
  "debtor": "employee",          // employee | client | third_party (кто ДОЛЖЕН сделать)
  "debtor_name": null,           // для third_party: «бухгалтер», «Сергей со склада»
  "creditor": "client",          // кому
  "action": "прислать коммерческое предложение",   // глагол в инфинитиве + объект
  "deadline": {
    "raw": "к среде",            // ВСЕГДА как сказано
    "type": "weekday",           // weekday | day_of_month | explicit_date | today | tomorrow |
                                 // day_after_tomorrow | in_days | in_weeks | this_week |
                                 // next_week | end_of_week | end_of_month | vague | none
    "value": "среда",            // нормализованное значение для type
    "resolved_start": "2026-10-14",  // вычисляет КОД
    "resolved_end": "2026-10-14",
    "flags": []                  // same_weekday_ambiguous | same_day_of_month | interval_collapsed |
                                 // vague | no_deadline | unparsed
  },
  "amount": {"value": 5000, "currency": "BYN", "approximate": true, "raw": "тысяч пять"},  // или null
  "condition": null,             // «если есть на складе»
  "status": "firm",              // firm | tentative | conditional | replaced | declined
  "replaces": null,              // id заменённого обязательства
  "review": "pending",           // pending | confirmed | edited | rejected (решение человека)
  "lifecycle": "open",           // open | done
  "evidence": [{"speaker": "employee", "t": 65.2, "quote": "КП давайте лучше к среде", "match_score": 96}],
  "verified": true               // цитата найдена в расшифровке
}

## Правила дат (опорная дата = дата звонка, Europe/Minsk)
- День недели («в/до/к пятнице/пятницы/среде»): ближайший БУДУЩИЙ такой день после даты
  звонка. Если совпадает с днём звонка («в пятницу», сказано в пятницу) → через неделю +
  флаг same_weekday_ambiguous. «До пятницы» = включительно эта пятница.
- Число месяца («до двадцатого», «к 15-му», «15 числа»): ближайшее будущее такое число (этот
  месяц, если число > дня звонка, иначе следующий). Равно дню звонка → флаг same_day_of_month.
  Порядковые числительные словами в родительном падеже («двадцатого», «тридцать первого») —
  обязательно поддержать.
- Явные даты «15 октября», «15.10» → ближайшая будущая такая дата.
- сегодня / завтра / послезавтра; «через N дней/недель» (N может быть словом: «через три дня»,
  «через неделю» = +7).
- «на следующей неделе» → интервал пн–вс следующей недели (start=пн, end=вс).
- «на этой неделе» → интервал от дня звонка до вс; если звонок в пт/сб/вс → флаг interval_collapsed.
- «до конца недели» → вс этой недели; «до конца месяца» → последний день месяца.
- «на днях», «в ближайшее время», «как можно скорее», «после праздников» → type vague, флаг vague.
- Срока нет → type none, флаг no_deadline.
- Не распознано → флаг unparsed, сырой текст сохраняется. Праздники РБ не учитываем.

## Проверка цитат
Нормализация (нижний регистр, ё→е, без пунктуации), rapidfuzz.fuzz.partial_ratio по каждому
сегменту, порог ~85; пробовать склейку соседних сегментов. Найдено → speaker и t (= start
сегмента) берутся из расшифровки, match_score записывается. Не найдено → verified=false, в
интерфейсе такое обязательство уходит в свёрнутый блок «Не подтверждено цитатой».

## Интерфейс (Streamlit, app.py)
Выбор клиента; заголовок карточки; колонки «Мы должны» (debtor=employee) и «Нам должны»
(debtor=client), блок «Третьи лица»; карточка обязательства: действие, срок «к среде → ср, 14.10»,
флаги бейджами, сумма, условие, статус, цитата курсивом, st.audio(audio_path, start_time=int(t))
если есть аудио, кнопки ✓ подтвердить / ✎ исправить / ✗ отклонить (сохраняются в store.json).
Намерения (tentative) — в свёрнутом блоке. Блок «Предложено закрыть» с кнопкой «Закрыть».
Блок «Загрузить звонок» (wav + телефон + дата/время → конвейер), если ASR доступен.
Должен работать на mock-данных без LLM и без аудио.

- Работай ТОЛЬКО внутри папки проекта. Без sudo. Не трогай ~/.bashrc, системные файлы,

  одна команда Bash не должна висеть дольше ~10 минут. Модели и кэши — в models/

- НИКОГДА не запускай долгоживущие серверы на переднем плане. Проверка Streamlit:
  timeout 40 .venv/bin/streamlit run app.py --server.headless true --server.port 8599 &

- Не задавай вопросов (никто не ответит). Решай сам, записывай решение в PROGRESS.md.
- Блокер (нужен sudo, не скачивается, не собирается) — не больше ~30–40 минут на обход, затем

  в THIRD_PARTY_LICENSES.md (лицензию проверять по метаданным пакета/карточке модели).
- Документы для людей (README, MORNING.md, PITCH.md и т.п.) — на русском.

## Право (для Q&A питча, не юридическое заключение)
Запись разговора — обработка персональных данных (позиция НЦЗПД РБ, Закон № 99-З).
Трансграничная передача — только в страны из перечня с надлежащей защитой (США в нём нет).
Согласие в РБ: письменно, электронный документ или иная электронная форма. Поэтому продукт
— модели внутри контура заказчика. Основание записи и текст уведомления — к юристу заказчика.

## MORNING.md — отчёт для команды (переписывай целиком в конце каждого запуска, ≤ 90 строк)
1. Статус на <время>: что готово (по задачам).
2. Как запустить (точные команды, проверенные тобой).
3. Что не работает / блокеры и что нужно от людей (например, sudo-команда).
4. Решения, принятые без команды.
5. Что сделать первым делом утром (3–5 пунктов).
6. Риски для демо.
